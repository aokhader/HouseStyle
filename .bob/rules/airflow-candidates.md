# apache/airflow — candidates and incidents

Patterns that did not clear the support threshold, plus one-off corrections deliberately kept out of the promoted set.

## Candidates (support below 3)

- `airflow-r056` **[api-design]** Shared literal constants in the Airflow UI (localStorage keys, gradients, pixel offsets, colours) must live in a `constants.ts` module — the global `src/constants/` one for cross-cutting keys, the feature folder's own for feature-local values — not inline in components. — support 2 (#69121, #53216)
- `airflow-r459` **[api-design]** Do not add public API to a widely shared base class when its only consumer lives in another package or layer; keep the member with the layer that uses it, and require at least one in-scope consumer before it joins the shared surface. — support 2 (#67717, #63358)
- `airflow-r463` **[api-design]** Do not use runtime `inspect` introspection to discover whether a callable accepts a parameter and pass arguments conditionally; make the parameter-presence decision on the caller side, or fix the caller/test to pass the expected arguments directly — support 2 (#69790, #56351)
- `airflow-r470` **[api-design]** Express sizing and spacing in Airflow UI components with Chakra UI token values (e.g. height={5}, p={2}), not raw CSS pixel strings passed through props or inline style/sx objects. — support 2 (#56344, #53657)
- `airflow-r473` **[api-design]** Implement behaviour common to all implementations of a pluggable hierarchy in its base class or a shared mixin (BaseExecutor, BaseCoordinator) rather than duplicating it in each concrete subclass. — support 2 (#65958, #62343)
- `airflow-r491` **[api-design]** Represent config-driven defaults consistently: keep the inline `conf.getboolean("operators", "default_deferrable", fallback=False)` expression in the runtime `__init__` signature rather than defaulting to `None` and resolving in the body, and use `...` for that parameter in the corresponding `.pyi` stub instead of a hardcoded literal — support 2 (#66979, #64321)
- `airflow-r510` **[async]** A trigger's `run()` must poll in a loop until its condition holds (bounded by a timeout where one applies), never a single await/check that can return nothing and fall back to stale data or exit silently — support 2 (#63915, #62790)
- `airflow-r511` **[async]** A trigger's timeout branch must always yield a `TriggerEvent` carrying the timeout status and a descriptive reason: do not `break`/`return` out of the polling loop, and wrap any cancellation side-effect in its own try/except so a failed cancel cannot replace the timeout event. — support 2 (#68799, #63614)
- `airflow-r522` **[commit-hygiene]** A new pre-commit hook's `files:` pattern must be narrowed to exactly the distributions and subpackages the rule applies to; never a bare `\.py$` or a whole-distribution glob — support 2 (#67367, #55416)
- `airflow-r523` **[commit-hygiene]** Adding a new UI translation locale requires an identified, dev-list-confirmed owner recorded in `.github/CODEOWNERS` and a locale guideline file at `.github/skills/airflow-translations/locales/<code>.md` — support 2 (#65630, #56353)
- `airflow-r526` **[commit-hygiene]** Hand-written lists inside `.github/` that mirror repository state (the provider inventory in issue templates, locale/namespace inventories in agent SKILL.md files) must be generated or validated by a prek/pre-commit hook rather than maintained by hand — support 2 (#64240, #62059)
- `airflow-r091` **[correctness]** Bulk endpoints must enforce the same authorization and state guards as their single-item counterparts: shared helpers must take the HTTP method as a parameter instead of hardcoding "PUT", and handle_bulk_delete must apply the single-delete state checks unless the relaxation is documented and intentional. — support 2 (#67095, #64288)
- `airflow-r118` **[correctness]** Handle symbols that moved or were added across versions with `try/except ImportError` fallbacks — stdlib first, then the backport — rather than `if AIRFLOW_V_x_y_PLUS` version branches. — support 2 (#54421, #53791)
- `airflow-r532` **[correctness]** airflow-core, including `airflow-core/tests/`, must not import task-SDK internals — `airflow.sdk._shared`, SDK-only exceptions from `airflow.sdk.exceptions`, or other private SDK paths; tests for SDK-only symbols live in the SDK test tree. — support 2 (#59883, #53389)
- `airflow-r541` **[correctness]** Build Helm value fallback chains with `or` and `hasKey`, not `| default`: `default` treats an empty map or false as unset, dropping both the global fallback and an intentional empty override — support 2 (#65027, #60677)
- `airflow-r553` **[correctness]** Diagnostics for conditions that are expected on paths the scheduler loop or the execution API re-runs every iteration or heartbeat must be logged at DEBUG; do not add INFO or WARNING logging to a hot fall-through branch. — support 2 (#65029, #62501)
- `airflow-r556` **[correctness]** Do not add redundant `try/except ImportError` compatibility shims: not in airflow-core tests for symbols that exist in the current core, and not in provider modules for imports that `airflow.providers.common.compat` already redirects. — support 2 (#64143, #54383)
- `airflow-r560` **[correctness]** Do not guard a Task SDK API client or supervisor-comms response with an `isinstance(resp, XResponse)` check whose else branch silently returns `[]`/`None`: these calls return their response model or raise `ServerResponseError`, so use the result directly and raise on an unexpected type. — support 2 (#66022, #56955)
- `airflow-r564` **[correctness]** Do not silence a failure with a blanket `except Exception: pass`-style handler: let the error propagate or chain it, or suppress only the specific expected exception types and log the suppression at debug. — support 2 (#64634, #53801)
- `airflow-r577` **[correctness]** Guard status-rendering components on the query's isLoading/isError flags; never render a settled status from `data?.field ?? fallback` while the query is in flight — support 2 (#62195, #56760)
- `airflow-r584` **[correctness]** In the Java/Kotlin SDK, report exceptions through the structured logger with the full stack trace via stackTraceToString(), never printStackTrace() to stderr or thrown.toString(); logger bridges must accept a nullable Throwable — support 2 (#68725, #65956)
- `airflow-r608` **[correctness]** Treat the numeric `status` field on the error object as the UI's API-error contract: read it as `(error as ExpandedApiError).status` / `error?.status` rather than `instanceof ApiError`, and attach `status` to any `Error` thrown from a raw `fetch()` inside a query function. — support 2 (#63477, #61560)
- `airflow-r612` **[correctness]** Use the enum member (`DagRunState`, `TaskInstanceState`, a provider status enum such as `DmsTaskWaiterStatus`) wherever a state is compared or passed; never a raw string literal that duplicates its value. — support 2 (#67524, #64939)
- `airflow-r177` **[database]** In SQLAlchemy 2.0 declarative models the Mapped[...] annotation is authoritative for nullability: it must agree with the column's nullable setting, and a redundant nullable=True kwarg must not be passed alongside Mapped[X | None]. — support 2 (#64571, #55954)
- `airflow-r630` **[database]** Alembic data migrations must not do per-row work over a whole table: batch UPDATEs into one `conn.execute(update().where(bindparam(...)), [rows])` and stage join keys into a temporary column instead of running a correlated join per row — support 2 (#66016, #63628)
- `airflow-r637` **[database]** Express "no referencing row" in ORM queries as a correlated ~exists(select(Child.fk).where(Child.fk == Parent.id)) anti-join rather than <col>.not_in(select(...)), and do not carry a redundant is_not(None) inside the EXISTS. — support 2 (#66210, #62501)
- `airflow-r649` **[database]** Write SQLAlchemy queries in the 2.0 style - session.scalar()/session.scalars() over select(Model).where(...) - not the legacy session.query(Model).filter(...) API or Select.filter(). — support 2 (#59918, #59823)
- `airflow-r206` **[docs]** Document a hook's connection configuration behaviour in its docstring: which `extra` keys are supported and in what precedence order, and exactly when a keyless fallback such as Application Default Credentials applies versus when an explicit key is still required. — support 2 (#64591, #53801)
- `airflow-r213` **[docs]** Help text for CLI date arguments that filter runs by partition or logical date must state the exact semantics: whether the end bound is inclusive or exclusive (and what value covers a whole calendar period), and that the calendar day is derived from the UTC instant rather than the user's local or the timetable's timezone. — support 2 (#67717, #66520)
- `airflow-r652` **[docs]** A changelog or release-note entry is a single concise line stating the user-visible change; PR narration, methodology notes, test-coverage clauses and the detailed explanation belong in the PR. — support 2 (#67137, #65569)
- `airflow-r660` **[docs]** A significant newsfragment describing an observability or process-management change must add the operator-visible impact and migration step (dashboards built on the old Gauge must move to Histogram aggregations; how to roll-restart the api-server on Kubernetes) — support 2 (#67233, #60940)
- `airflow-r663` **[docs]** Add a bullet to a provider's changelog.rst only when that provider's own source files change; a PR limited to test files, to another provider's tests, or to non-functional pyproject.toml marker comments gets no entry. — support 2 (#66424, #60706)
- `airflow-r677` **[docs]** Example DAGs must be plain, self-contained and copy-pasteable against current main: no try/except ImportError compatibility shims for older Airflow versions or optional dependencies, and no imports of helpers shared across example DAG files. — support 2 (#65172, #53389)
- `airflow-r699` **[docs]** When a provider operator or hook gains a new documented parameter or changes its documented behaviour (auth types, supported options), update the class docstring and the matching provider RST guide under `providers/<name>/docs/` in the same PR. — support 2 (#64538, #53801)
- `airflow-r707` **[naming]** In executor methods that also reference `airflow.executors.workloads`, name the sequence parameter `workload_items`; do not keep the colliding name `workloads` or alias the module import to work around the collision. — support 2 (#63657, #62984)
- `airflow-r724` **[performance]** Do not perform per-row database work inside a loop over DAGs, task instances, or event rows: hoist the query out of the loop, batch it, or pass the already-fetched data in, and eager-load any relationship the loop dereferences (joinedload/selectinload) rather than letting it lazy-load per row. — support 2 (#63568, #63546)
- `airflow-r265` **[providers]** Do not import underscore-prefixed internals of a third-party package (e.g. `google.genai._api_client`, `structlog._output.WRITE_LOCKS`); where such an import is unavoidable, wrap it in `try/except ImportError` with a `None` fallback, guard every use of it, and add tests that catch upstream removal. — support 2 (#68479, #65121)
- `airflow-r274` **[providers]** Import symbols that have been migrated to the Task SDK from their airflow.sdk.* public path, not from the legacy airflow-core module (e.g. XCOM_RETURN_KEY from the Task SDK BaseXCom rather than airflow.models.xcom; exceptions from airflow.sdk.exceptions rather than airflow.exceptions). — support 2 (#58356, #54505)
- `airflow-r290` **[providers]** Raise a dependency version floor — on a cross-provider `apache-airflow-providers-*` requirement or on an optional extra — only for a genuinely breaking change; an additive parameter with a `None` default or a new optional feature does not justify one. — support 2 (#69234, #60706)
- `airflow-r733` **[providers]** A dependency pin or upper bound added to a provider's `pyproject.toml` as a workaround must carry a comment naming the upstream issue and the condition under which the cap can be lifted. — support 2 (#63520, #62962)
- `airflow-r734` **[providers]** A dependency used by only one optional code path must not appear in a provider's mandatory `dependencies`; put it in a named extras group and guard the import, especially when it is experimental or a protocol upgrade — support 2 (#63518, #52976)
- `airflow-r745` **[providers]** Every package a provider imports directly must be declared as a dependency in that provider's `pyproject.toml` in the same PR; do not rely on it arriving transitively. — support 2 (#68479, #65991)
- `airflow-r747` **[providers]** Every version-compatibility shim in a provider must carry a comment naming the exact release involved — the minimum `>=X.Y.Z` that exports the symbol, or a `# TODO: Remove once minimum supported Airflow version is X.Y`. — support 2 (#66674, #60855)
- `airflow-r750` **[providers]** Import an optional third-party SDK once - at module level behind `try`/`except ImportError`, or in a single shared helper that raises `AirflowOptionalProviderFeatureException` - rather than repeating a bare `import` inside each hook or operator method — support 2 (#62790, #61866)
- `airflow-r754` **[providers]** Operators, triggers, notifiers and listeners must reach a third-party service through the provider's Hook class (sync or async) rather than constructing the underlying client or session inline. — support 2 (#68082, #56160)
- `airflow-r759` **[providers]** Take a service's scheme, host and port from the Airflow connection (and its extras) named by the operator's `*_conn_id`; do not hardcode them or re-parse them out of another string such as a queue URI. — support 2 (#67118, #53556)
- `airflow-r762` **[providers]** Values in `provider.yaml` that a user is meant to copy - config `example:` values and `ui-field-behaviour` `placeholders` - must be literal, runtime-valid values (the codec name the code accepts, valid JSON for a Connection `extra`), never file-extension aliases or Python expressions — support 2 (#68283, #62790)
- `airflow-r763` **[providers]** When a provider change raises the minimum Airflow core or Task SDK version it actually requires — swapping a core import for the `common.compat.sdk` equivalent, or dropping SDK-specific parameters from a system test — update that provider's declared minimum version in the same PR. — support 2 (#62962, #59883)
- `airflow-r773` **[security]** FastAPI apps and routers exposed by a provider plugin must declare their own auth dependencies at route or router level — `Depends(requires_access_*)` for authentication, plus `GetUserDep` alongside `SessionDep` on state-mutating handlers — rather than relying on the parent app's middleware. — support 2 (#63081, #55301)
- `airflow-r774` **[security]** Never log or print a Connection, a ConnectionResult, `Connection.get_uri()` output, or any credential-bearing string — including temporary debug output; redact it, or apply the security code-scanning suppression, before logging. — support 2 (#57744, #56191)
- `airflow-r786` **[testing]** Build test fixtures from the real library type the production code inspects - a V1PodStatus for a pod's status, a real sqlite3.OperationalError as an exception's orig - rather than a plain dict or string stand-in. — support 2 (#67900, #59097)
