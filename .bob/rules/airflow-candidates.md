# apache/airflow — candidates and incidents

Patterns that did not clear the support threshold, plus one-off corrections deliberately kept out of the promoted set.

## Candidates (support below 3)

- `airflow-r034` **[api-design]** Expose a value callers need to control - an operation timeout, a flag the paired trigger consumes - as a constructor parameter on the operator or hook and pass it through, instead of hard-coding it at the construction site or fixing it in a module-level constant. — support 2 (#68942, #64770)
- `airflow-r045` **[api-design]** Make UI HTTP calls through the generated React Query layer - the OpenAPI-generated react-query hooks in airflow-core, useQuery/useMutation over Axios in the Edge plugin UI - never a raw fetch or a direct axios call from a component. — support 2 (#62369, #54994)
- `airflow-r056` **[api-design]** Shared literal constants in the Airflow UI (localStorage keys, gradients, pixel offsets, colours) must live in a `constants.ts` module — the global `src/constants/` one for cross-cutting keys, the feature folder's own for feature-local values — not inline in components. — support 2 (#69121, #53216)
- `airflow-r070` **[async]** Measure deadlines and elapsed durations in triggers and operators with time.monotonic(), and build the deadline values in their tests with that same clock. — support 2 (#66815, #64051)
- `airflow-r078` **[commit-hygiene]** Use a bugfix.rst newsfragment rather than significant.rst for internal fixes with no observable user-facing behaviour change, and omit the fragment entirely when there is no user impact. — support 2 (#65239, #62501)
- `airflow-r086` **[correctness]** airflow-core, including its tests, must not import Task SDK internals: no airflow.sdk._shared or other private SDK namespaces, and no exception from airflow/sdk/exceptions.py that is only raised inside the SDK - those tests belong in the SDK test tree. — support 2 (#59883, #53389)
- `airflow-r091` **[correctness]** Bulk endpoints must enforce the same authorization and state guards as their single-item counterparts: shared helpers must take the HTTP method as a parameter instead of hardcoding "PUT", and handle_bulk_delete must apply the single-delete state checks unless the relaxation is documented and intentional. — support 2 (#67095, #64288)
- `airflow-r096` **[correctness]** Compare enum-typed values as Enum members: use the provider's or Airflow's Enum rather than raw string literals, and do not reach for .value before the comparison. — support 2 (#67524, #61833)
- `airflow-r110` **[correctness]** `execute_complete` must branch on `event["status"]` and handle every status its paired Trigger can emit — raising for error, cancelled and timeout statuses — before reading any payload field as a success. — support 2 (#64274, #64051)
- `airflow-r118` **[correctness]** Handle symbols that moved or were added across versions with `try/except ImportError` fallbacks — stdlib first, then the backport — rather than `if AIRFLOW_V_x_y_PLUS` version branches. — support 2 (#54421, #53791)
- `airflow-r127` **[correctness]** Instance attributes — resource handles such as a consumer or client, and state flags such as submission status — must be initialised in `__init__` and, for resources, reset to `None` after cleanup; do not first-assign or reset them inside `run()`, `submit()` or `execute()`. — support 2 (#65991, #64612)
- `airflow-r132` **[correctness]** Log a caught exception with its full exception information - self.log.exception(...) or exc_info=True as a structlog keyword - rather than suppressing it silently or recording only str(exc). — support 2 (#68548, #66584)
- `airflow-r139` **[correctness]** Read boolean Airflow configuration options with conf.getboolean(), never conf.get() or conf.has_option, and never pass a fallback that contradicts the option's declared default in config.yml. — support 2 (#65493, #63884)
- `airflow-r141` **[correctness]** Reject an invalid query-parameter value with HTTP 400 instead of silently falling back to it: an unparseable cursor token and an empty regex pattern must both raise rather than reach the query. — support 2 (#64845, #64610)
- `airflow-r168` **[database]** Add every related object to the session first and flush once at the end rather than flushing part-way through, in production write paths and test setup alike, unless a later setup query genuinely needs the earlier flush. — support 2 (#61372, #58248)
- `airflow-r177` **[database]** In SQLAlchemy 2.0 declarative models the Mapped[...] annotation is authoritative for nullability: it must agree with the column's nullable setting, and a redundant nullable=True kwarg must not be passed alongside Mapped[X | None]. — support 2 (#64571, #55954)
- `airflow-r181` **[database]** Tie a new migration to the next unreleased version: an airflow-core migration adds its _REVISION_HEADS_MAP entry under that version and keeps the map chaining monotonically through the previous head, and a provider migration file is named for the next unreleased provider version - rename it before merge if a new minor has been cut since the branch opened. — support 2 (#62343, #61646)
- `airflow-r188` **[docs]** Add a bullet to a provider's changelog.rst only when that provider's own source files change: a PR touching only test files, another provider's tests, or non-functional pyproject.toml marker comments gets no entry or release section. — support 2 (#66424, #60706)
- `airflow-r206` **[docs]** Document a hook's connection configuration behaviour in its docstring: which `extra` keys are supported and in what precedence order, and exactly when a keyless fallback such as Application Default Credentials applies versus when an explicit key is still required. — support 2 (#64591, #53801)
- `airflow-r213` **[docs]** Help text for CLI date arguments that filter runs by partition or logical date must state the exact semantics: whether the end bound is inclusive or exclusive (and what value covers a whole calendar period), and that the calendar day is derived from the UTC instant rather than the user's local or the timetable's timezone. — support 2 (#67717, #66520)
- `airflow-r244` **[performance]** Do not perform per-row database work inside a loop over DAGs, task instances or task-map entries: hoist the query outside the loop, batch it, or pass the already-fetched data in; if the data comes from a SQLAlchemy relationship, eager-load it instead of touching the attribute lazily inside the loop. — support 2 (#63568, #63546)
- `airflow-r248` **[performance]** In hot-path queries, select only the columns actually used rather than the whole ORM entity: grid and UI endpoints must enumerate their columns instead of select(TaskInstance)/select(DagRun), and with_row_locks selects must fetch only the primary key when only the id is used. — support 2 (#59183, #53216)
- `airflow-r257` **[providers]** A provider must not reach for an airflow-core symbol or attribute that does not exist in its minimum supported core version: guard the import behind a version or ImportError check, and read a newer attribute with getattr(obj, 'attr', default) rather than accessing it directly. — support 2 (#69005, #62984)
- `airflow-r260` **[providers]** Annotate a provider compatibility shim with the Airflow version it is tied to: an ImportError fallback for a Task SDK symbol names the minimum >=X.Y.Z release that exports it, and a workaround for an older core API carries a `# TODO: Remove once minimum supported Airflow version is X.Y` comment. — support 2 (#66674, #60855)
- `airflow-r265` **[providers]** Do not import underscore-prefixed internals of a third-party package (e.g. `google.genai._api_client`, `structlog._output.WRITE_LOCKS`); where such an import is unavoidable, wrap it in `try/except ImportError` with a `None` fallback, guard every use of it, and add tests that catch upstream removal. — support 2 (#68479, #65121)
- `airflow-r268` **[providers]** Every package a provider imports directly must be declared as a direct dependency in that provider's pyproject.toml, in the same PR as the import; do not rely on it arriving transitively. — support 2 (#68479, #65991)
- `airflow-r270` **[providers]** Everything belonging to a provider lives inside that provider's own directory: its prek/pre-commit hooks and their supporting scripts under providers/<name>/, and its logo and image assets under providers/<name>/ rather than a parallel top-level folder. — support 2 (#62261, #56456)
- `airflow-r274` **[providers]** Import symbols that have been migrated to the Task SDK from their airflow.sdk.* public path, not from the legacy airflow-core module (e.g. XCOM_RETURN_KEY from the Task SDK BaseXCom rather than airflow.models.xcom; exceptions from airflow.sdk.exceptions rather than airflow.exceptions). — support 2 (#58356, #54505)
- `airflow-r275` **[providers]** In a deferrable operator, persist operator links and push the job or query identifier to XCom as soon as it is obtained - before self.defer() and before entering any polling loop - not after the wait completes. — support 2 (#69477, #64274)
- `airflow-r290` **[providers]** Raise a dependency version floor — on a cross-provider `apache-airflow-providers-*` requirement or on an optional extra — only for a genuinely breaking change; an additive parameter with a `None` default or a new optional feature does not justify one. — support 2 (#69234, #60706)
- `airflow-r316` **[security]** Never log or print a connection, its URI, or any credential string - at any log level, including temporary debug prints; redact the value or use the security code-scanning suppression first. — support 2 (#57744, #56191)
- `airflow-r327` **[testing]** Do not reach for pytest's caplog to prove behaviour: assert on observable behaviour or return values, and in Kubernetes and integration tests capture log output with mocks instead. — support 2 (#63878, #53598)
- `airflow-r329` **[testing]** E2e helpers and assertions must wait for the UI to settle rather than reading immediately after an action: navigation helpers must wait for a key element to be visible before returning, and post-click assertions (e.g. pagination) must use `expect.poll()`. — support 2 (#60449, #59943)
- `airflow-r015` **[api-design]** A concrete Task SDK class exported from the public API must implement every abstract method of its base (including `to_upstream()` on partition mappers); leave it abstract or unexported until it does. — support 1 (#64571)
